## 1. Translating objects (Object Detection) $\rightarrow$ Eigenvalue & Connected-Component Adjacency Matrices [4] 

* The Math: An object in a 2D grid is a connected subgraph. We represent the grid coordinates as a graph using an Adjacency Matrix ($\mathbf{A}$) of size $900 \times 900$, where $\mathbf{A}_{i,j} = 1.0$ if pixel $i$ and pixel $j$ are neighbors and share the same color.
* ONNX Implementation: Finding independent objects is equivalent to computing matrix powers to discover connected components. Raising the adjacency matrix to a power via consecutive MatMul nodes propagates the connectivity:
$$\mathbf{M}_{\text{objects}} = \text{Sign}(\mathbf{A} + \mathbf{A}^2 + \mathbf{A}^3 + \dots + \mathbf{A}^k)$$ 
This provides an isolated, block-diagonal mask for every independent object on the board using simple matrix multiplication series.

## 2. Translating fill (Color Operations) $\rightarrow$ Hadamard (Element-wise) Inversion Masks

* The Math: Instead of checking pixel indices sequentially with an if loop, use vector spaces. Let $\mathbf{X}_c$ be the one-hot binary slice for color $c$.
* ONNX Implementation: To replace color $c_1$ with color $c_2$ only inside a bounded zone matrix $\mathbf{B}$, you perform an inversion subtraction followed by a vector addition:
$$\mathbf{X}_{\text{new}} = \mathbf{X}_{c_1} - (\mathbf{X}_{c_1} \odot \mathbf{B}) + (\mathbf{B} \odot \mathbf{X}_{c_2})$$ 
This acts as a clean mathematical switch gate, avoiding NonZero or structural branching nodes.

## 3. Translating mapply / compose $\rightarrow$ Kronecker Tensor Products ($\otimes$)

* The Math: These high-order operators run a transformation repeatedly across sub-grids (like tiling a canvas or applying a rule to smaller sub-blocks). This maps directly to a Kronecker Product.
* ONNX Implementation: If a $3 \times 3$ stamp matrix $\mathbf{S}$ needs to be mapped across every positive sector of a $10 \times 10$ layout matrix $\mathbf{L}$, the total output grid is computed as:
$$\mathbf{Y} = \mathbf{L} \otimes \mathbf{S}$$ 
In ONNX, this is achieved by reshaping $\mathbf{L}$ and $\mathbf{S}$, executing an element-wise broadcasting multiplication node (Mul), and reshaping the output straight into the target $30 \times 30$ configuration.

## 4. Translating rbind / lbind $\rightarrow$ Block Splicing Projection Matrices

* The Math: Concatenating rows or columns is a linear mapping operation.
* ONNX Implementation: Create two static binary projection matrices, $\mathbf{P}_A$ and $\mathbf{P}_B$. To stitch matrix $\mathbf{A}$ and matrix $\mathbf{B}$ side-by-side:
$$\mathbf{Y} = \mathbf{P}_A \mathbf{A} + \mathbf{P}_B \mathbf{B}$$ 
The projection constants act as a coordinate anchor, automatically sorting the incoming pixel values into their correct locations during execution.
