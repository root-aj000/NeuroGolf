# NeuroGolf Strategy Review

## Project Overview

Implement ONNX models for 400 ARC-style tasks from the neurogolf-2026 dataset.
Competition constraints: opset 10, no loops/ScatterND/filters, single input/output, static shapes, ≤1.44 MB.

---

## Strategy 1: D4 Permutation (`01/`)

**Approach:** Reshape → Transpose → Gather → Transpose → Reshape pipeline to express D4 symmetry group transformations.

**Result:** 4/400 tasks solved (task87, task140, task179, task380)
**ONNX size:** ~2KB each

**Limitation:** Only handles rotation/mirror symmetry. Cannot express color mapping, object detection, or spatial reasoning.

---

## Strategy 2: Conv2d Logic Gates (`02/`)

**Approach:** 1x1 Conv2d for color mapping + 3x3 Conv2d for neighborhood rules → bias → ReLU → Mul(color_diff) → Add(input).

**Result:** 4/400 tasks solved (task16, task276, task309, task337) — all color-mapping tasks

**Key Finding:** Neighborhood models fail because most tasks have multiple rules for different colors but the model only implements the first rule. Multi-rule support requires branching/conditionals not expressible in pure Conv2d.

---

## Strategy 3: Arc-DSL Analysis (`03/`)

**Approach:** Match each neurogolf task to a pre-written DSL solver from `arc-dsl/solvers.py`, extract primitives used.

**Result:** 399/400 tasks matched to solvers. 1 unmatched (task361), 2 verification failures on 4th example (task339, task346).

### Primitive Categories

**ONNX-Compatible (safe):**
- Transform: `rot90`, `rot180`, `rot270`, `hmirror`, `vmirror`, `dmirror`, `cmirror`
- Grid ops: `crop`, `hconcat`, `vconcat`, `hsplit`, `vsplit`, `tophalf`, `bottomhalf`, `lefthalf`, `righthalf`
- Color ops: `replace`, `switch`, `fill`, `underfill`, `recolor`, `cover`
- Spatial: `ofcolor`, `asindices`, `delta`, `box`, `border`
- Geometry: `ulcorner`, `urcorner`, `llcorner`, `lrcorner`, `center`, `height`, `width`, `shape`, `size`
- Scaling: `upscale`, `downscale`
- Creation: `canvas`

**ONNX-Incompatible (banned/complex):**
- Object detection: `objects`, `colorfilter`, `sizefilter`, `mfilter`, `sfilter`, `partition`, `fgpartition`
- Higher-order: `apply`, `mapply`, `compose`, `fork`, `chain`, `rbind`, `lbind`
- Movement: `move`, `shift`, `gravitate`, `shoot`
- Complex fill: `paint` (needs ScatterND)

## Strategy 4: ONNX-Compatible Primitive Subset (`04/`)

**Approach:** Filter 399 matched tasks to only those solvable with ONNX-compatible primitives. Build hand-crafted ONNX models for each.

**Rationale:**
- We know exactly which tasks use which primitives (from Strategy 3)
- ~50-100 tasks likely use only simple transformations
- Highest expected payoff — targeted, not speculative

**Target Tasks:**
- Tasks using only: rotations, mirrors, color replacement, scaling, cropping, concatenation
- Avoid tasks requiring: objects, mapply, compose, fork, paint, move

**Results:**
- 53 tasks identified as ONNX-compatible (simple primitives only)
- **20 tasks successfully built and verified**
- 31 tasks skipped (complex intermediate patterns)
- 2 tasks mismatch (task067, task108 - need further work)

**Solved tasks by method:**
- rot180: 2 (task087, task140)
- vmirror: 1 (task150)
- hmirror: 1 (task155)
- rot270: 1 (task380)
- dmirror: 2 (task179, task241)
- switch(5,8): 1 (task337)

- upscale(2): 1 (task307)
- upscale(3): 1 (task223)
- multi_switch(4): 2 (task016, task276)
